# 부가가치 서비스 아키텍처

## 1. 서비스 개요

부가가치는 부산 공공임대주택을 찾는 사용자가 신청 가능성이 있는 임대 유형을 확인하고, 예산·희망 지역·생활 취향에 맞는 주택을 추천받을 수 있도록 돕는 웹 서비스다.

현재 시스템은 **Next.js 기반의 프론트엔드 중심 단일 애플리케이션**으로 구성되어 있다. 별도의 애플리케이션 백엔드나 데이터베이스는 없으며, 자격 판정과 추천 계산은 대부분 사용자 브라우저에서 실행된다. AI 채팅 기능만 Vercel Serverless Function을 통해 외부 AI API를 호출한다.

---

## 2. 핵심 사용자 흐름

1. 사용자가 자격 확인 질문에 답한다.
2. 브라우저에서 공공임대 유형별 자격 규칙을 실행한다.
3. 자격 결과와 사용자 입력을 `localStorage`에 저장한다.
4. 사용자가 예산, 희망 지역, 자주 가는 장소, 생활 인프라, 교육 및 생활 취향을 입력한다.
5. 예산과 지역 조건으로 주택 후보를 필터링한다.
6. 사전 계산된 주택 및 주변 인프라 데이터를 이용해 후보별 추천 점수를 계산한다.
7. 추천 결과를 목록, 지도, 주택 상세 화면으로 제공한다.
8. AI 갈붕이를 이용하면 Vercel의 `/api/chat`이 주택 데이터를 AI 컨텍스트에 포함해 외부 AI API로 전달하고, 스트리밍 응답을 사용자에게 반환한다.

---

## 3. 전체 서비스 구성

### 3.1 사용자 브라우저

브라우저는 서비스의 주요 UI와 비즈니스 로직을 실행한다.

- 랜딩 페이지
- 공공임대 자격 확인
- 생활 취향 설문
- 맞춤 주택 추천
- 전체 주택 지도 탐색
- 주택 상세 정보
- AI 갈붕이 채팅
- 커뮤니티
- 게스트 마이페이지

React Client Component가 사용자 입력과 화면 상태를 관리하며, 자격 판정과 추천 점수 계산도 브라우저에서 수행한다.

### 3.2 상태 및 사용자 데이터

Zustand를 상태 관리 도구로 사용한다.

- `eligibility.store.ts`: 자격 확인 입력 및 판정 결과
- `preferences.store.ts`: 예산, 지역, 생활 취향
- `user.store.ts`: 저장한 주택, 최근 본 주택, 알림 설정, 신청 체크리스트

Zustand의 `persist` 미들웨어를 통해 상태를 브라우저 `localStorage`에 저장한다. 로그인이나 사용자 계정 서버는 없으며 입력 데이터는 서버 데이터베이스로 전송되지 않는다.

### 3.3 도메인 로직

화면과 계산 규칙을 분리하기 위해 주요 비즈니스 로직을 `src/features` 아래에 배치한다.

- 자격 판정 규칙
- 자격 기준 연도 및 소득·자산 구간
- 예산 및 희망 지역 하드 필터
- 생활 취향 가중치 계산
- 결측 항목 가중치 재정규화
- 추천 근거 생성
- 주택 신청 체크리스트

자격 판정과 추천 로직은 가능한 한 부수효과 없는 순수 함수로 작성되어 있다.

### 3.4 정적 주택 및 인프라 데이터

서비스는 런타임 데이터베이스 대신 빌드 전에 생성된 JSON 데이터를 사용한다.

주요 생성 데이터:

- `data/housing_index.json`
  - 4개 공공임대 원본 데이터 통합
  - 원본 84,002행
  - 355개 건물
  - 9,022개 물리 호실
  - 930개 임대 가격 조건
- `data/nearby_infra.json`
  - 건물별 필수 생활시설
  - 취향 가게
  - 어린이집 및 학교
  - 보정 거리와 최근접 시설

원본 데이터 전체를 브라우저에 전달하지 않고, 전처리 스크립트가 건물 단위로 정규화하고 필요한 거리와 점수를 미리 계산한다.

### 3.5 지도

지도 화면은 Kakao Maps JavaScript SDK를 사용한다.

- 주택 마커 및 가격 라벨
- 같은 위치의 주택 그룹화
- 지도 이동 영역에 따른 결과 갱신
- 주택 선택과 목록 선택 동기화
- 주택 주변 생활 인프라 표시

`NEXT_PUBLIC_KAKAO_MAP_KEY`가 설정되지 않은 환경에서는 외부 지도 요청 없이 목업 지도 컴포넌트로 대체된다.

### 3.6 AI 채팅

AI 채팅은 브라우저에서 외부 AI API를 직접 호출하지 않는다.

1. 브라우저가 `/api/chat`으로 최근 대화와 선택한 주택 ID를 전송한다.
2. Vercel Serverless Function이 주택 목록과 서비스 안내를 시스템 프롬프트에 추가한다.
3. OpenAI SDK를 사용해 OpenAI 호환 AI API를 호출한다.
4. AI 응답을 텍스트 스트림으로 브라우저에 반환한다.
5. 응답에 포함된 추천 주택 ID를 파싱해 지도 및 주택 카드와 연결한다.

기본 제공자는 Upstage Solar이며 다음 환경변수로 다른 OpenAI 호환 제공자나 모델로 변경할 수 있다.

- `AI_BASE_URL`
- `AI_MODEL`
- `AI_API_KEY`

API 키는 서버 환경변수에만 저장하고 클라이언트 번들에는 포함하지 않는다.

### 3.7 배포

애플리케이션은 Vercel 프로젝트에 연결되어 있다.

- 정적 페이지 및 공개 리소스: Vercel Edge/CDN
- Next.js 애플리케이션: Vercel Next.js Runtime
- `/api/chat`: Vercel Serverless Function, Node.js Runtime
- 이미지, 영상, 로고, 지도 마커: `public` 정적 리소스

## 4. 데이터 전처리 파이프라인

### 입력 데이터

- 공공임대주택 원본 4종
- 병원, 대형마트, 공원, 도서관, 체육시설, 지하철역
- 어린이집, 유치원, 초등학교, 중학교, 고등학교
- 음식점, 카페, 편의점, 운동시설 등 취향 시설

### 전처리 작업

- 주소 및 좌표가 유효한 데이터 선별
- 임대 유형과 주소를 기준으로 건물 그룹화
- 중복된 물리 호실 및 가격 조건 제거
- 좌표계를 EPSG:5186으로 변환
- 부산 우회계수를 적용한 보정 거리 계산
- 시설 접근성 점수 계산
- 업종 분포 및 동네 분위기 백분위 계산
- 건물별 최근접 생활 인프라 추출

### 출력 데이터

- `housing_index.json`
- `nearby_infra.json`
- 지도 인프라 마커용 SVG 마크업

생성된 데이터는 Next.js 빌드 결과에 포함되어 배포된다. 운영 중에 원본 데이터베이스를 조회하거나 거리 계산을 다시 수행하지 않는다.

## 5. 외부 연동

| 외부 시스템 | 사용 목적 | 호출 위치 |
| --- | --- | --- |
| Kakao Maps JavaScript SDK | 지도, 마커, 좌표 기반 탐색 | 사용자 브라우저 |
| Upstage 또는 OpenAI 호환 API | AI 주택 추천 및 공공임대 안내 | Vercel `/api/chat` |
| BMC·LH 신청 사이트 | 실제 모집공고 확인 및 신청 | 사용자 브라우저의 외부 링크 |

## 6. 현재 존재하지 않는 구성요소

아키텍처 이미지를 만들 때 아직 구현되지 않은 시스템을 현재 구성처럼 표현하지 않도록 주의한다.

- 별도 백엔드 애플리케이션 서버
- 사용자 인증 및 회원 계정
- 운영 데이터베이스
- 실시간 공고 수집 서버
- 실제 커뮤니티 게시글 저장 API
- 관리자 시스템
- 메시지 큐 또는 이벤트 스트리밍
- Redis 등의 서버 캐시
- 자체 지도 서버

커뮤니티, 후기, 주소 검색 일부는 현재 정적 목업 데이터로 동작한다.

## 7. 아키텍처 이미지 생성용 GPT 프롬프트

아래 프롬프트를 GPT 이미지 생성 기능에 그대로 입력한다.

```text
한국어로 된 전문적인 서비스 시스템 아키텍처 다이어그램을 만들어줘.

서비스 이름은 "부가가치"이고, 부산 공공임대주택 자격 확인 및 생활 취향 기반 추천 웹 서비스야.

이미지는 16:9 가로형, 흰색 또는 매우 밝은 배경, 깔끔한 플랫 벡터 인포그래픽 스타일로 만들어줘. 발표 자료와 기술 문서에 사용할 수 있도록 기업용 아키텍처 다이어그램 느낌으로 구성해줘. 글자는 선명하고 한국어가 깨지지 않아야 해. 장식적인 일러스트보다 시스템의 연결 관계가 명확하게 보이는 것이 중요해.

전체 구조를 왼쪽에서 오른쪽으로 배치해줘.

1. 가장 왼쪽: "사용자 브라우저"
   - 사용자 아이콘과 웹 브라우저 아이콘
   - 내부에 다음 기능을 작은 카드로 표시:
     "자격 확인"
     "생활 취향 설정"
     "맞춤 주택 추천"
     "지도 탐색"
     "주택 상세"
     "AI 갈붕이"
     "커뮤니티"
     "마이페이지"

2. 브라우저 내부 처리 영역:
   - "React 19 UI"
   - "Zustand 상태 관리"
   - "자격 판정 규칙"
   - "예산·지역 필터"
   - "생활 취향 점수 계산"
   - "localStorage"
   Zustand와 localStorage 사이에는 양방향 화살표를 표시해줘.
   자격 판정과 추천 계산이 브라우저에서 실행된다는 점을 보여줘.

3. 중앙: "Vercel / Next.js 16"
   - "Edge / CDN"
   - "Next.js App Router"
   - "정적 페이지 및 리소스"
   - 별도 강조 박스로 "Serverless Function: POST /api/chat"
   사용자는 Vercel을 통해 웹 애플리케이션에 접속하고, AI 채팅 요청만 /api/chat으로 전달되는 흐름을 표시해줘.

4. 중앙 하단: "사전 계산된 정적 데이터"
   - 데이터베이스 실린더가 아니라 JSON 파일 아이콘을 사용해줘.
   - "housing_index.json"
   - "355개 건물"
   - "9,022개 호실"
   - "930개 가격 조건"
   - "nearby_infra.json"
   - "건물별 생활 인프라·거리"
   이 데이터가 브라우저의 자격·추천·지도·상세 기능과 /api/chat에 공급되는 화살표를 그려줘.

5. 오른쪽 외부 시스템:
   - "Kakao Maps JavaScript SDK"
     브라우저의 지도 탐색 기능과 직접 연결
   - "Upstage Solar / OpenAI 호환 API"
     Vercel의 /api/chat Serverless Function하고만 연결
   AI API 키는 서버 환경변수에서 보호된다는 작은 자물쇠 아이콘과 "서버 환경변수" 라벨을 표시해줘.

6. 아래쪽에 별도의 "빌드 타임 데이터 파이프라인"을 긴 흐름으로 표시:
   "공공임대 원본 84,002행"
   +
   "병원·마트·공원·학교·상가 데이터"
   →
   "Node.js 전처리"
   →
   "주소 정규화·중복 제거·좌표 변환·거리 및 점수 계산"
   →
   "housing_index.json + nearby_infra.json"
   →
   "Next.js Build"
   →
   "Vercel 배포"

색상은 역할별로 통일해줘:
   - 사용자 및 브라우저: 부드러운 파란색
   - Vercel 및 Next.js: 짙은 남색
   - 정적 데이터: 청록색
   - 외부 서비스: 보라색
   - 빌드 파이프라인: 주황색

화살표 라벨:
   - 브라우저 ↔ localStorage: "사용자 입력 저장"
   - 브라우저 → /api/chat: "최근 대화 + 선택 주택"
   - /api/chat → AI API: "스트리밍 요청"
   - AI API → /api/chat → 브라우저: "텍스트 스트림 + 추천 주택 ID"
   - 브라우저 → Kakao Maps: "지도 SDK 호출"

다이어그램 하단에 짧은 핵심 문장을 넣어줘:
"프론트엔드 중심 구조 · DB/로그인 서버 없음 · AI 채팅만 서버리스 API 사용"

중요:
   - 운영 데이터베이스, 인증 서버, Redis, 메시지 큐, 별도 백엔드 마이크로서비스는 그리지 마.
   - JSON 정적 데이터와 빌드 타임 전처리 구조를 명확히 표현해.
   - 모든 라벨은 한국어로 작성해.
   - 로고나 특정 기업의 실제 상표 이미지는 사용하지 말고 일반적인 아이콘으로 표현해.
```

## 8. 이미지 검수 기준

생성된 이미지가 아래 조건을 만족하는지 확인한다.

- 브라우저에서 자격 판정과 추천 계산이 실행되는가?
- 운영 DB가 아니라 정적 JSON 데이터로 표현되어 있는가?
- AI 호출이 브라우저에서 직접 나가지 않고 `/api/chat`을 통과하는가?
- Kakao 지도만 브라우저에서 외부 SDK로 직접 연결되는가?
- 빌드 타임 데이터 전처리 흐름과 서비스 런타임 구조가 구분되는가?
- `localStorage`와 사용자 상태가 연결되어 있는가?
- 존재하지 않는 인증 서버, DB, Redis, 메시지 큐가 포함되지 않았는가?
