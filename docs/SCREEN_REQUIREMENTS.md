# SCREEN REQUIREMENTS — 부가가치

> 온보딩 UI 이미지 반영: 서비스명 **부가가치**, 프라이머리 **teal/emerald**, **좌측 질문카드 + 우측 "입력 요약" 스티키 사이드바** 2단 레이아웃, 상단 4스텝 스테퍼(체크 완료 표시), 세그먼트형 선택 버튼, 하단 이전/다음 CTA, 완료 카드. (Claude Design 편집기·좌측 대화창·공유 팝업 등은 참고 대상 아님.)

## 0. 공통 디자인 시스템
- 색: primary teal `#0d9488`계열, 성공/통과 emerald, 탈락 amber/red(색+아이콘 병기). 배경 라이트 그레이, 카드 흰색 라운드.
- 레이아웃: 데스크톱 2단(main 2/3 + summary 1/3), 모바일 1단(요약은 상단 접이식/하단 시트).
- 컴포넌트: `Stepper`, `SummarySidebar`, `SegmentedChoice`, `QuestionCard`(제목+왜묻는가 도움말), `PrimaryCTA`, 상시 `DisclaimerBanner`("추천은 자격 확정이 아니에요").

## 1. B1 랜딩
- 요구: 한 줄 소개, "공공임대 추천 시작하기"(주요 CTA), 동작 과정(3~4스텝), 지원 유형 5종 카드, 추천 기준 설명, 최근 모집공고 예시(mock), "추천≠자격확정" 고지, "로그인 없이 체험", 모바일/데스크톱 헤더.
- 상태: `NOT_STARTED`. 재방문 시 "이어서 하기"(RESTORED) 진입점.

## 2. B2 1단계 자격 (이미지 직접 반영)
공통 셸: 스테퍼 `A 주택소유 → B 가구나이 → C 소득자산 → D 지역` + 우측 입력요약(본인주택/세대원주택/제한이력/만나이/가구원/월평균소득/총자산/자동차/부산거주, 미입력 `—`) + 푸터 "입력 정보는 자격 판정에만 사용돼요".

- **스텝 A(게이트):** 3개 라디오. "주택 소유 여부를 확인할게요" + 도움말. 본인 주택 `있음` → 즉시 종료 화면 전환.
- **스텝 B:** 생년월일 date input(→만나이), 가구원 구성(본인 고정 + "가구원 추가" 관계 선택), 태아 포함 토글. "다음"은 B 완료 시 C 활성.
- **스텝 C:** "소득과 자산을 입력해 주세요". 월소득 = 가구원 수 줄의 5구간 세그먼트(예: 280만), 총자산 8구간(예: 15,000만), 자동차 3단(미보유/4,542만 이하/초과). "참여 소득 상세" 접이식.
- **스텝 D:** 부산 거주 라디오. "완료".
- **완료 카드:** 체크 아이콘 + "기본 자격 정보를 모두 확인했어요" + "처음부터 다시".
- **1-1 중간 결과:** 통과 후보/제외+사유/추가확인(NEEDS_MORE)/1-2 예고. 후보 0개 → 종료 화면.
- **즉시 종료 화면(IMMEDIATE_REJECT):** 결과 요약·탈락 사유·입력 수정·실제 공고 확인 안내·조건 변경 후 재진단 안내.
- **1-2 세부:** 후보 유형만 순차 카드(계층/순위/출산/부모입력). 제외 유형 블록 렌더 금지. 재개발 카드에 **"2025년 공고 기준" 배지+툴팁**.

## 3. B3 2단계 취향
- **진입 안내:** 신청 가능 유형·후보 주택 수·"자격 아닌 추천 순서"·건너뛰기/수정 안내.
- **Q0 예산:** 보증금/월세 최대 입력. 0개 → 완화 제안. (하드필터 배지)
- **Q1 지역:** 구·군 복수 칩 + "상관없어요".
- **Q2~Q6:** 각 카드 상단 가중치 배지 + "왜 묻는가" + 건너뛰기. Q2 주소 mock 자동완성+라벨, Q3 시설 복수칩, Q4 게이트→시설칩, Q5 칩10+직접입력, Q6 3택.
- **분석 중:** 스켈레톤/프로그레스(ANALYZING).

## 4. B4 리스트 + 지도
- 데스크톱 분할(좌 리스트/우 지도), 모바일 지도↔리스트 토글.
- 지도: 카카오(키 있으면), 없으면 **mock map**(실제 요청 금지). 마커·클러스터링·hover 강조·선택 시 요약 카드.
- 정렬: 추천순/월세순/보증금순/거리순. 필터: 유형/모집중/구·군. 즐겨찾기.
- 각 카드: 정성 추천 이유 + 항목별 점수 접기 + "확인 필요 자격조건". 선택 추천 조건 요약 바.
- 상태: `HAS_RESULTS`/`NO_RESULTS`/`MAP_LOADING`/`API_ERROR_MOCK`.

## 5. B5 상세
- 주택명·유형·주소·모집상태·신청기간·공급세대수·전용면적·보증금·월세.
- 지도+주변시설, 추천 점수(항목별+원본값), 추천 이유, **자격 판정 결과+확인할 조건(병렬, 혼합 아님)**, 공식 공고 링크, 저장/공유, 리뷰(태그: 교통·소음·편의시설·관리상태).
- 상태: `SAVED`.

## 6. B6 커뮤니티
- 공고 공유·입주 후기·Q&A, 지역별/유형별 게시판, 인기/최신, 검색, 글쓰기 mock, 신고·운영정책 안내.

## 7. B7 마이페이지
- 자격 진단 결과·추천 조건·저장 주택·최근 본 주택·관심 공고·설문 다시하기·입력 수정·알림 설정 UI·개인정보/데이터 삭제·로그아웃 mock.

## 8. 화면 상태 매트릭스 (요구 18종)
`NOT_STARTED / IN_PROGRESS / RESTORED / VALIDATION_ERROR / IMMEDIATE_REJECT / PARTIAL_PASS / ALL_REJECT / STAGE1_DONE / STAGE2_IN_PROGRESS / FILTER_EMPTY / ANALYZING / HAS_RESULTS / NO_RESULTS / MAP_LOADING / API_ERROR_MOCK / SAVED / GUEST` — 각 화면이 자신에 해당하는 상태의 빈/에러/로딩 뷰를 mock으로 제공.

## 9. 데이터 입출력 / 예외 / 접근성 / 개인정보 / 백엔드 / 완료조건
- **입출력:** 각 화면은 store 구독 + services 호출 결과 렌더.
- **예외:** 가드 실패 리다이렉트, 필터 0개 완화 제안, mock 오류 재시도.
- **접근성:** 스테퍼 `aria-current`, radiogroup, 지도 대체 리스트, 대비 AA, 키보드 완주.
- **개인정보:** 요약 사이드바 하단 고지, 삭제 화면 명시.
- **백엔드:** 지도/시설/추천은 adapter 결과만 표시 → 실데이터 교체 시 화면 불변.
- **완료조건:** B1~B7이 mock으로 렌더되고 18개 상태가 재현되며 이미지의 1-1 온보딩 구조가 그대로 구현됨.
