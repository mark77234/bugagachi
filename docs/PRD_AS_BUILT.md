# PRD (구현 기준) — 부가가치

부산 공공임대주택 **자격 확인 + 생활 취향 추천** 서비스의 **현재 구현 상태**를 기술한 문서다.

- [`docs/PRD.md`](./PRD.md) 는 착수 시점의 **기획 PRD**(정책 결정 필요 항목 포함)이고, 이 문서는 그 이후 실제로 구현된 결과를 정리한 **as-built PRD**다.
- 두 문서가 어긋나는 부분은 **이 문서가 최신**이다.
- 기준 커밋: `dc0e10d` 이후 작업분 · 작성일 2026-07-25

---

## 1. 제품 개요

### 1.1 한 줄 정의

부산에서 공공임대주택을 찾는 사람이 **① 신청 가능성이 있는 유형을 먼저 확인하고 → ② 예산·지역·생활 취향에 맞춰 순위화된 주택을 추천받는** 프론트엔드 웹 서비스.

### 1.2 해결하는 문제

| 문제 | 서비스의 대응 |
| --- | --- |
| 공공임대 유형별 자격 기준이 흩어져 있고 용어가 어렵다 | 쉬운 질문 4단계(A~D)로 5개 유형을 한 번에 판정 |
| "신청 가능한지"와 "살기 좋은지"가 뒤섞여 판단이 어렵다 | 자격(통과/탈락)과 취향(0~1 점수)을 **절대 합치지 않고 병렬 표시** |
| 추천 결과의 근거를 알 수 없다 | 축별 점수 + 원본값(거리·개수·백분위)을 항상 병기 |
| 로그인·개인정보 입력 부담 | 로그인 없이 전 기능 사용, 입력값은 브라우저(localStorage)에만 저장 |

### 1.3 불변 원칙 (구현에 반영됨)

1. **자격 판정과 취향 점수를 하나의 숫자로 합치지 않는다.**
2. **예산·희망지역은 점수가 아니라 하드필터**다 (초과 시 후보에서 제거).
3. **추천은 법적 자격 확정이 아니다** — 모든 결과 화면에 `Disclaimer` 상시 노출.
4. **탈락에는 사유 + 재확인 항목 + 재진단 경로**를 항상 동반한다.
5. **점수는 원본 값과 정성적 근거로 설명**한다 ("상위 20%", "보정거리 7.2km").
6. **결측은 0점이 아니라 항목 제외**로 처리하고, 남은 축의 가중치를 재정규화한다.
7. **기준연도**: 소득·자산 2026년 기준, **재개발임대만 2025년 공고 기준**(UI에 배지로 명시).

    housing/      신청 체크리스트
    user/         저장·최근본·알림·체크 상태
  config/         자격 기준 상수 (2026 / 2025 재개발)
  mocks/          데이터 어댑터 (실데이터 JSON + 목업)
  lib/            좌표·포맷·스토리지 유틸

**설계 규칙**
- 자격 기준 수치는 전부 `src/config/eligibility-config.2026.ts` / `.2025.ts`에만 존재한다. 화면은 이 파일을 직접 참조하지 않는다.
- 추천 가중치·거리 구간은 `src/features/recommendation/scoring.config.ts`에 격리한다.
- 판정·스코어링은 부수효과 없는 순수 함수 → 추후 서버 API로 교체 시 입출력 타입만 유지하면 된다.

## 3. 데이터

### 3.1 주택 재고 (`data/busan_rental_scores.json`)

1행 = **1호실**. 화면에서는 `address_norm` 기준으로 **건물 단위로 묶어** 표시하고, 예산 필터는 건물 안의 개별 호실 조건으로 판정한다.

| 항목 | 값 |
| --- | --- |
| 원본 행 수 | 634행 |
| 유효 행 (주소·구·좌표 보유) | **308행** |
| 제외 행 (전 필드 결측) | 326행 |
| 건물 수 | **38개** |
| 임대조건(보증금·월세) 보유 | 259행 / 나머지는 "가격 미등록" |
| 임대유형 | 매입임대 (단일) |
| 행정구역 | **수영구** (단일) |

`*_dist_m`은 EPSG:5186 투영 후 **직선거리 × 1.291(부산 우회계수)** 이 적용된 보정거리이며, `*_score`는 전 재고를 모집단으로 사전계산된 0~1 값이다. **런타임에서 거리·백분위를 다시 계산하지 않는다.**

### 3.2 목업 데이터

## 5. 화면별 기능 명세

### 5.1 랜딩 `/`

섹션 순서 (현재 구조):

1. **서비스 진입 카드** — `나에게 맞는 집 추천받기`(전체 폭) → `AI 갈붕이` · `지도에서 전체 주택 둘러보기`(좌·우 1개씩, 각 절반 폭). 카드 배경은 마스코트 영상.
2. **신뢰 안내 바** — 재고 수량 · 브라우저 저장 · 공고 확인 필수.
3. **히어로** — "부산에서 나에게 맞는 공공임대주택을 찾아보세요" + 시작 CTA.
4. **이렇게 도와드려요** — 5개 기능 영상 섹션 (자격 확인 / 맞춤 추천 / AI 갈붕이 / 지도 탐색 / 전체 둘러보기).
5. **맞춤 추천 이용 과정** — 4단계 카드.
6. **지원 임대 유형** — 5종 배지 (재개발임대는 `2025년 기준` 배지).

### 5.2 1단계 자격 확인 `/eligibility`

**흐름**: `공통 입력(A→B→C→D)` → `1-1 중간 결과` → `1-2 유형별 세부(후보 유형만)` → `최종 요약`
게이트: 스텝 A에서 **본인 명의 주택 소유** 선택 시 확인 다이얼로그 → 전 유형 종료 화면.
자격 확인을 건너뛰고 2단계 탐색 모드로 진입하는 경로도 제공한다.

#### 스텝 A — 주택 소유
- 본인 명의 주택 소유 여부 (게이트)
- 세대원 중 주택 소유자 여부
- 공공임대 계약 중 · 불법 전대/양도(4년 내) · 재당첨 제한 이력

#### 스텝 B — 생년월일 · 세대구성원
- **생년월일을 입력해 주세요** → 만 나이 자동 계산
- **주민등록상 세대구성원을 관계별로 알려주세요**
  - 본인 — 항상 1명 고정
  - 배우자 — 있음/없음
  - 부모·조부모 / 자녀 / 임신 중 태아 — 인원수 스테퍼
  - 총 인원 상한 8명 (소득·자산 기준표가 8인까지 정의)
- 안내: 세대구성원 정의, **형제자매·삼촌·조카는 제외**, 태아 포함 자동 계산

#### 스텝 C — 소득 · 자산
소득·자산을 **본인 단독**과 **세대 전원 합계**로 분리해 받는다. 유형마다 심사 기준이 다르기 때문이다.

| 상황 | 본인 질문 | 세대 질문 |
| --- | --- | --- |
| 세대 1인 | 받음 (= 세대 값으로 사용) | 생략 |
| 세대 2인 이상 + 만 19~39세 | 받음 | 받음 |
| 세대 2인 이상 + 그 외 나이 | 생략 | 받음 |

- 본인 월소득: **본인의 월평균 소득(세전)은?** — 1인 가구 5구간
- 세대 월소득: **세대구성원 전원의 월소득 합계는?** — 세대원 수별 5구간
- 본인 총자산: **본인이 보유한 총자산은? (부동산+자동차+금융+기타−부채)** — 8구간
- 세대 총자산: **세대구성원 전원의 총자산 합계는?** — 8구간
- 자동차: **세대구성원이 보유한 차량 중 가장 비싼 차의 가액은?** — 미보유 / 4,542만원 이하 / 초과

입력 방식은 **금액 직접 입력이 기본**이고, "금액을 모르면 범위로 선택" 접이식 구간 카드를 함께 제공한다.

#### 스텝 D — 지역
- 부산광역시 거주 여부 (재개발임대·매입임대 일반의 필수 조건)

#### 결과 화면
- 1-1 중간 결과: 유형별 `PASS` / `FAIL` / `NEEDS_MORE` + 사유 + 재확인 항목
- 1-2 세부: 후보 유형별 계층·순위 입력 (통합 계층, 행복 계층, 재개발 출산자녀, 매입 순위, 매입청년 부모 합산 등)
- 최종 요약: 통과 유형 목록 → 2단계로 이동 CTA. 결과는 마이페이지용 스냅샷으로 저장.

### 5.3 2단계 생활 취향 설정 `/preferences`

**게이트**: 1단계 통과 유형이 없고 건너뛰기도 아니면 진입 차단 → 1단계 안내.

| 순서 | 질문 | 성격 | 가중치 |
| --- | --- | --- | --- |
| 1 | 예산 (보증금·월임대료 상한) | **하드필터** | — |
| 2 | 희망 지역 (구·군 복수 선택 / 상관없음) | **하드필터** | — |
| 3 | 자주 가는 장소 (직장·학교 1곳) | 점수 | 0.30 |
| 4 | 필요한 기반시설 | 점수 | 0.25 |
| 5 | 돌봄·교육 | 점수 | 0.20 |
| 6 | 취향 가게 (최대 5개) | 점수 | 0.15 |
| 7 | 동네 분위기 (0=조용 ~ 1=번화) | 점수 | 0.10 |

**세부 사양**
- **예산**: 보증금 0~5,000만원(50만원 단위), 월 임대료 0~50만원(1만원 단위) **슬라이더**. 진입 시 기본값(1,000만원 / 25만원)을 확정하고, 빠른 선택 칩(1,000·3,000·5,000 / 15·25·35)을 함께 제공.
- **기반시설**: 종합병원 · 대형마트 · 공원 · **공공도서관** · 생활체육시설 · 지하철역
- **돌봄·교육**: 필요 여부 → 어린이집 · 유치원 · 초 · 중 · 고
- **취향 가게 칩(10종)**: 식당 · 뷰티 · 카페 · 편의점/슈퍼마켓 · 운동/스포츠 · 베이커리 · 치킨 · 주점 · 입시/예체능 학원 · 독서실/스터디카페
- **동네 분위기**: 슬라이더 + "상관없어요"
- 3~7번은 **건너뛰기** 가능하며, 건너뛴 축의 가중치는 남은 축에 재분배된다.
- 우측 `내 선호 요약` 사이드바가 입력값을 실시간 반영한다.
- 계산식·백분위 산출 방법 등 내부 알고리즘 설명은 화면에 노출하지 않는다.

### 5.4 추천 목록 · 지도 `/recommendations`

- 분석 로딩 상태 → 결과 리스트
- **정렬**: 추천순 / 월세순 / 보증금순 / 거리순(자주 가는 장소 기준)
- **필터**: 임대유형, 구·군
- **뷰 토글**: 리스트 ↔ 지도 (선택 항목 동기화)
- 카드: 적합도 배지, 대표 임대조건, 상위 2개 축 근거, 저장 토글
- **빈 결과 처리**: 예산 초과 / 지역 불일치를 구분해 사유와 근접 후보 수를 안내

`S0`~`S9` 구조:

## 6. 자격 판정 로직

### 6.1 대상 유형 (5종)

`통합공공임대` · `행복주택` · `재개발임대` · `매입임대 일반` · `매입임대 청년`

### 6.2 1-1 공통 필터 (`stage1Common`)

1. **게이트**: 본인 주택 소유 → 전 유형 즉시 `FAIL`
2. 유형별로 총자산 / 자동차 가액 / 월소득 / 세대원 유주택 / 부산 거주 / 연령 조건 검사
3. 소득 상한 = `기준소득[가구원수] × (배율 + 가산율)` — 기준은 중위소득(MEDIAN) 또는 도시근로자(URBAN)
4. **본인/세대 이중 기준**: 1-1 시점에는 계층이 정해지지 않았으므로, **'본인' 계층을 가진 유형**(통합·행복·매입청년)은 세대 기준과 본인 기준 중 **유리한 쪽**으로 후보를 남긴다. 본인 기준일 때 소득 상한은 **1인 가구 기준**을 쓴다.
5. 통과 → `NEEDS_MORE`(1-2 진행 대상), 탈락 → `FAIL` + 사유

### 6.3 1-2 유형별 세부 (`stage1Detail`)

계층/순위별 규칙표(`STAGE2_RULES`)의 `householderDef`에 따라 심사 기준이 갈린다.

| `householderDef` | 적용 값 | 해당 계층 |
| --- | --- | --- |
| `self` (본인) | 본인 소득·자산, 1인 가구 소득 상한 | 통합:청년, 행복:대학생/청년/사회초년생, 매입임대 청년 전 순위 |
| `household` (세대) | 세대 합계 소득·자산, 세대원 수 기준 | 그 외 전 계층 |

- **통합공공임대**: 계층(청년/신혼한부모/고령자/일반), 신혼은 혼인 84개월 + 맞벌이 가산
- **행복주택**: 계층 6종, 대학생은 자동차 소유 불가, 재학·소득활동 상태는 재확인 항목
- **재개발임대**: 출산 자녀 수에 따른 자산·자동차 완화표
- **매입임대 일반**: 1순위(서류 확인) / 2순위(도시근로자 50% 소득)
- **매입임대 청년**: 만 19~39세 필수. 1순위(서류) / 2순위(본인+부모 합산이 도시근로자 100%·자산 3.45억 이내) / 3순위(**본인** 소득 100%·자산 2.51억)

결과는 `PASS` / `FAIL` / `NEEDS_MORE` + `reasons` + `checkLater`(공고에서 재확인할 항목)로 반환된다.

## 7. 추천 스코어링

### 7.1 파이프라인

```
자격 통과 유형으로 후보 풀 구성
  → 예산 하드필터(호실 단위)   → 0건이면 근접 후보 수와 함께 안내
  → 지역 하드필터              → 0건이면 안내
  → 축별 점수 계산 (응답한 축만)
  → 계산 불가 축 제외 후 가중치 재정규화 (합 = 1)
  → 가중합 → 정렬 → 정성 근거 생성
```

### 7.2 축별 계산

| 축 | 가중치 | 계산 |
| --- | --- | --- |
| 자주 가는 장소 | 0.30 | 보정거리(EPSG:5186 × 1.291) 기준 5km=1.0 / 10km=0.7 / 30km=0 선형 감쇠 |
| 기반시설 | 0.25 | 선택 시설 `*_score` 동일가중 평균. 병원·공공도서관은 차량 기준(5·10·15·20km), 나머지는 도보 기준(750m·1.5·3·6km) |
| 돌봄·교육 | 0.20 | 어린이집 375m·750m·1.5km·3km, 그 외 750m·1.5·3·6km |
| 취향 가게 | 0.15 | 반경 750m 업종별 점포 수 백분위의 동일가중 평균 |
| 동네 분위기 | 0.10 | 아래 수식 참조 |

동네 분위기 점수:

```
vibe = (1 - abs(c - t) / max(t, 1 - t)) × (1 - 0.5 × n × (1 - t))

c = 반경 750m 상가 총량 백분위
n = 소음업종 구성비 백분위
t = 사용자가 선택한 목표 위치 (0=조용 ~ 1=번화)
```

앞항은 목표 `t`에 꼭짓점을 둔 삼각형(선택한 분위기에 가까울수록 높은 점수), 뒤항은 소음 감점(최대 50%, 번화를 선호할수록 약해짐)이다.

### 7.3 결측 처리

- 계산 불가한 항목(데이터 없음)은 **0점이 아니라 축에서 제외**한다.
- 선택한 칩이 전부 계산 불가면 그 축 전체가 빠지고 가중치가 재분배된다.
  → 치킨 · 주점 · 입시/예체능 학원만 선택하면 취향 가게 축이 통째로 제외된다.
- 최종 점수는 **동일 응답 내 상대 순위**로만 쓰고, 서로 다른 사용자 간 비교에는 쓰지 않는다.
- 화면에는 숫자 대신 정성 라벨(`매우 잘 맞아요` / `잘 맞아요` / `무난해요` / `조건 확인 필요`)과 축별 근거를 함께 노출한다.

## 10. 현재 한계 · 다음 과제

### 10.1 데이터

1. **커버리지** — 유효 데이터가 수영구 매입임대 38개 건물뿐이다. 통합공공임대·행복주택·재개발임대는 판정 로직만 있고 매칭될 주택이 없다. → **재고 데이터 확대가 최우선**.
2. **주택 이미지** — 전량 미보유. 크롤링 또는 로드뷰 API 연동 필요.
3. **가격 기준일·최종 갱신일** — 열 자체가 없어 신뢰도 표기가 불완전하다.
4. **가게 3종(치킨·주점·입시/예체능 학원)** — 점포 수 데이터가 없어 선택해도 점수에 반영되지 않는다.
5. **모집 일정** — 실시간 공고 데이터가 없어 모집 상태는 항상 "공고 확인 필요"다.

### 10.2 기능

- 커뮤니티 글쓰기·리뷰는 목업이며 서버 저장이 없다.
- 알림 설정은 UI만 존재한다.
- 주소 자동완성은 목업 사전이며 실제 지오코딩 API가 아니다.
- 로그인·계정이 없어 기기 간 동기화가 불가하다.
