# PRD — 부가가치 (부산 공공임대 자격 확인 + 상권·취향 추천)

> 표기 규칙
> - `[문서 원문]` : 첨부된 1단계 자격요건 문서(`ELIGIBILITY.md` / `stage1_filter.py`)를 Source of Truth로 그대로 반영한 값.
> - `[정책 결정 필요]` : 문서·프롬프트 어디에도 근거가 없어 별도 결정이 필요한 사항. 임의 확정 금지.
> - `[문서 내 불일치 — 확인 필요]` : 문서 내부(코드 vs 표)가 서로 다른 값. 기본값을 두되 확정 전 검증 필요.

## 1. 목적

부산 공공임대주택 신청을 고려하는 사용자가,
1. **신청 자격을 먼저 판정**(1단계)받고,
2. 자격을 통과한 주택만을 대상으로 **예산·희망지역(하드필터) + 생활취향(가중치 점수)** 으로 순위화된 추천(2단계)을 받는

**프론트엔드 전용** 웹서비스다. 백엔드·DB·실제 인증·실제 추천 API는 구현하지 않으며, 모든 데이터·판정은 mock data와 프론트엔드 순수함수로 구현한다. 단, 추후 백엔드 연결이 쉽도록 타입·서비스 레이어를 UI와 분리한다.

### 불변 원칙 (product invariants)
1. **자격 판정과 취향 점수를 절대 혼합하지 않는다.** 자격 = 통과/탈락(불리언), 취향 = 0~1 점수. 하나의 숫자로 합치지 않는다.
2. **예산·희망지역은 점수가 아니라 하드필터**다. 기준 초과/불일치 주택은 후보에서 *제거*(감점 아님).
3. **추천은 법적 자격 확정이 아니다.** 모든 결과 화면에 "실제 신청 가능 여부는 모집공고 확인 필요"를 상시 노출한다.
4. **탈락은 사유 + 재확인 항목 + 재진단 경로**를 항상 동반한다. 결과만 던지지 않는다.
5. **각 질문마다 "왜 묻는가"를 설명**한다.
6. **점수는 원본 값과 정성적 근거로 설명**한다("상위 20%", "보정거리 7.2km"). 벌거벗은 숫자만 노출 금지.
7. **자격 기준연도**: 소득·자산 모두 2026년 기준. **재개발임대만 2025년 공고 기준**(2026 미발표) — UI에 명시. `[문서 원문]`

## 2. 판정 대상 (5개 카테고리)

`통합공공임대(TONGHAP)` · `행복주택(HAENGBOK)` · `재개발임대(JAEGAEBAL)` · `매입임대 일반(MAEIP_ILBAN)` · `매입임대 청년(MAEIP_CHUNG)`.
매입임대는 자격 구조가 다른 청년/일반으로 분리한다. `[문서 원문]`

## 3. 사용자 시나리오

- **S1 (자격 확인 우선):** 무주택 청년이 자신이 어떤 유형에 신청 가능한지 모른다 → 1-1 공통 입력 → 1-2 유형별 → 통과 유형·탈락 사유 확인.
- **S2 (탈락 후 재도전):** 본인 주택 소유로 즉시 종료 → 사유·재확인 안내 → 조건 변경 후 재진단.
- **S3 (추천 탐색):** 자격 통과 후 예산·지역·취향 입력 → 리스트/지도에서 정성 근거와 함께 추천 확인 → 상세 → 저장.
- **S4 (부분 취향):** 돌봄·교육이 불필요한 1인 가구가 해당 축을 건너뜀 → 남은 축으로 재정규화 추천 `[정책 결정 필요]`.
- **S5 (커뮤니티/재방문):** 비로그인 사용자가 저장한 주택·진단 결과를 마이페이지에서 다시 확인, 커뮤니티에서 후기 열람.

## 4. 기능 요구사항 (요약, 상세는 각 SPEC 문서)

- **B1 랜딩**: 서비스 소개, 시작 CTA, 동작 과정, 지원 유형, 추천 기준 설명, 최근 공고 예시(mock), 자격확정 아님 고지, 비로그인 체험, 반응형 헤더.
- **B2 1단계 자격**: 1-1 공통(A 주택소유 게이트 → B 가구·나이 → C 소득·자산 → D 지역) → 1-1 중간 결과 → 1-2 유형별 세부(후보 유형만) → 1단계 완료 결과/종료. 실동작 수준.
- **B3 2단계 취향**: Q0 예산·Q1 지역(하드필터) → Q2~Q6 취향(가중치). 실동작 수준.
- **추천 계산 모듈**: 하드필터 → 축별 점수 → 가중합 → 정성 근거 생성. mock.
- **B4 리스트·지도**: 카카오 지도(키 없으면 mock), 리스트↔지도 동기화, 정렬·필터·즐겨찾기.
- **B5 상세**: 항목별 점수·원본값·자격결과·확인할조건·공고링크·리뷰.
- **B7 마이페이지**: 진단결과·추천조건·저장·최근·재설문·삭제·알림 UI.
- **B6 커뮤니티**: 지역/유형 게시판·인기/최신·검색·글쓰기 mock·신고/운영정책.

## 5. 비기능 요구사항

- **성능**: 시설 거리 계산은 mock 데이터 기준 클라이언트 계산. Q5 백분위는 사전계산 테이블 조회(런타임 반복계산 금지). 초기 진입 LCP < 2.5s 목표(정적 랜딩).
- **유지보수**: 자격 규칙·점수 상수는 전부 `config/`에 격리. 화면 컴포넌트는 상수를 직접 하드코딩하지 않는다.
- **확장성**: 지오코딩·거리·시설조회는 adapter 인터페이스 뒤에 둔다(추후 카카오/도로명 API 교체).
- **정확성/추적성**: 자격 판정 결과에 적용 규칙 근거(기준연도·기준값)를 함께 보관, 상세에서 열람 가능.
- **국제화**: 1차 한국어. 문자열은 상수/사전 분리 권장.

## 6. 화면 상태 (전역 상태 머신)

`NOT_STARTED → IN_PROGRESS → (RESTORED) → VALIDATION_ERROR → IMMEDIATE_REJECT | PARTIAL_PASS | ALL_REJECT → STAGE1_DONE → STAGE2_IN_PROGRESS → FILTER_EMPTY → ANALYZING → HAS_RESULTS | NO_RESULTS → MAP_LOADING → API_ERROR_MOCK → SAVED`, 그리고 횡단 상태 `GUEST(비로그인)`. 각 상태의 화면 정의는 `SCREEN_REQUIREMENTS.md` 참조.

## 7. 데이터 입력/출력

- 입력: 1단계 공통/세부 자격 입력, 2단계 예산·지역·취향 입력. (스키마 `FRONTEND_DATA_MODEL.md`)
- 출력: 유형별 자격 결과(PASS/FAIL/NEEDS_MORE + 사유 + 확인할조건), 추천 리스트(정성 근거 + 원본값 + 항목별 점수).

## 8. 예외 상황

- 본인 주택 소유 → 전 유형 즉시 종료(게이트). `[문서 원문]`
- 1-1 후보 0개 → 종료 화면.
- 2단계 예산/지역 필터 결과 0개 → 예산·지역 완화 제안 UI.
- 유효성 검사 실패(생년월일 미래, 소득 미선택 등) → 인라인 에러, 진행 차단.
- 카카오 지도 키 부재 → mock map 컴포넌트(실제 요청 금지).
- mock API 오류 상태 재현(로딩/에러/빈결과).

## 9. 접근성

- 모든 폼 컨트롤 라벨·`aria-describedby`로 "왜 묻는가" 연결. 라디오/세그먼트는 `role=radiogroup`.
- 스텝 진행은 `aria-current="step"`. 키보드만으로 전 플로우 완주 가능.
- 색만으로 통과/탈락 구분 금지(아이콘+텍스트 병기). 명도대비 WCAG AA.
- 지도는 리스트 대체 뷰 제공(지도 없이도 전체 기능 사용 가능).

## 10. 개인정보 주의사항

- 생년월일·소득·자산은 **자격 판정에만 사용**하고 서버 전송하지 않음(이미지의 "입력 정보는 자격 판정에만 사용돼요" 카피 준수).
- 클라이언트 저장(`localStorage`)만 사용, 마이페이지에서 **명시적 삭제** 제공.
- 주소(자주 가는 장소)는 좌표 변환 후 원문 주소 저장 최소화. URL 쿼리에 개인정보 금지.

## 11. 추후 백엔드 연동 포인트

- `services/eligibility` → 규칙 엔진을 서버 API로 교체 가능(입출력 타입 고정).
- `services/geo` adapter → 실제 지오코딩/좌표변환 API.
- `services/facilities` → CSV/DB 로더로 교체(현재 mock, 타입·위치는 정의).
- `services/recommendation` → 서버 스코어링으로 교체.
- 인증 → 실제 세션으로 교체(현재 GUEST mock).

## 12. 완료 조건 (Definition of Done)

1. B2·B3가 실제 입력→판정→후보 산출→추천까지 mock으로 end-to-end 동작.
2. 5개 유형 1-1/1-2 판정이 `stage1_filter.py` 로직과 동일 결과(검증 케이스: "27세 청년·부모 유주택·자산 2억 → 1-1 후보 통합·행복·매입청년, 1-2 매입청년 3순위 통과"). `[문서 원문]`
3. 모든 자격 상수가 `eligibility-config.2026.ts` / `.2025.ts`(재개발)에 격리.
4. 추천 결과가 점수 대신 정성 근거+원본값으로 표시.
5. 전 상태(6장) mock 재현, 접근성·개인정보 원칙 충족.
6. `[정책 결정 필요]`·`[문서 내 불일치]` 항목이 코드 주석과 본 문서에 명시.
