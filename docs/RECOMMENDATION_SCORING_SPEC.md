# RECOMMENDATION SCORING SPEC — 2단계 상권·취향 추천

> **Source of Truth:** `data/busan_rental_scores_description.md`와
> `data/busan_rental_scores.json`. 가중치·거리 매듭·우회계수는 원문 그대로 사용한다.
> 실제 JSON은 634행 중 유효 308호실·38개 주소 건물이며, 나머지 326행은 모든 핵심 필드가 비어 있어 재고에서 제외한다.

## 1. 목적
1단계를 통과한 주택만을 대상으로, 예산·지역 하드필터를 적용하고 5개 취향 축을 0~1 점수로 산정해 가중합으로 순위화한다. **자격 값은 이 파이프라인에 입력하지 않는다**(혼합 금지).

## 2. 사용자 시나리오
- 자격 통과 유형의 JSON 재고 → 호실별 예산 필터 → 건물별 후보 접기 → 지역 필터 → 취향 점수화 → 정성 근거와 함께 정렬 노출.
- 돌봄·교육 불필요 사용자 → 해당 축 제외 → 남은 축 가중치를 비율대로 재분배해 합을 1로 만든다.

## 3. 파이프라인 (순수함수 체인, `services/recommendation`)
```
passedUnits (1단계 PASS 주택)
 → applyBudgetFilter(units, Q0)      // 하드필터, 점수화 X
 → applyRegionFilter(units, Q1)      // 하드필터, 점수화 X
 → (0개 → RelaxSuggestion 반환)
 → units.map(u => {
      axis = {
        frequent:     Q2 answered ? scoreFrequent(u, dests)      : null,   // 0.30
        infra:        Q3 answered ? scoreInfra(u, cats)          : null,   // 0.25
        education:    Q4.enabled  ? scoreEducation(u, cats)      : null,   // 0.20
        store:        Q5 answered ? scoreStore(u, sel, dist)     : null,   // 0.15
        neighborhood: Q6 answered ? scoreNeighborhood(u, target) : null,   // 0.10
      }
      weights = normalize(answeredAxes)     // [정책] 재정규화(권장) vs 0점
      final   = Σ(axis[k] * weights[k])     // ∈ [0,1]
      reasons = buildReasons(axis, rawValues)
   })
 → sort(final desc)
```

## 4. 공통 유틸: 계단형 점수 (선형보간)
```ts
// breakpoints: [{d: 거리, s: 점수}, ...] 오름차순. 구간 사이 선형보간, 밖은 clamp.
stepScore(distance, breakpoints) → number ∈ [0,1]
```

## 5. Q0 예산 (하드필터, 필수) `[문서 원문]`
- 입력: 보증금 최대(만원), 월 임대료 최대(만원).
- 처리: 초과 주택 **제거**(점수화 금지 — "예산 밖인데 상위 노출" 모순 방지).
- 같은 건물에서도 호실별 금액으로 비교하며, 두 상한을 모두 만족하는 호실이 하나 이상 있을 때 건물을 후보로 남긴다.
- `deposit_krw` 또는 `rent_krw`가 결측인 호실은 비교에서 제외하고 상세 화면에 `임대조건 미공개`로 표시한다.
- `priority_rank`는 금액 필터에 사용하지 않는다.
- 0개 → 예산 완화 제안 UI(현재 컷 대비 근접 주택 수 표시).

## 6. Q1 지역 (하드필터) `[문서 원문]`
- 입력: 부산 구·군 복수 선택 + "상관없어요".
- 처리: 선택 구·군 주택만 유지("상관없어요"=전체). 점수화 X. 0개 → 지역 완화 제안.

## 7. Q2 자주 가는 장소 — 가중치 **0.30** `[문서 원문]`
- 입력: 직장 또는 학교 도로명주소 + 사용자 지정 라벨(단일, 선택).
- 처리: 지오코딩 → **EPSG:5186 좌표변환** → 투영좌표 유클리드 거리 × 1.291(부산 평균 우회계수) → `stepScore`.
- 계단: `(5km, 1.0) — (10km, 0.7) — (30km, 0)` 선형보간.
- 프론트: 실제 주소 API 없이 **mock 자동완성 + 샘플 좌표**. adapter(`services/geo/geocoder`)로 추후 실 API 교체.

## 8. Q3 필수 기반시설 — 가중치 **0.25** `[문서 원문]`
- 입력(복수): 종합병원 / 대형마트 / 공원 / 도서관 / 생활체육시설 / 지하철역.
- 처리: JSON의 카테고리별 사전계산 `*_score`를 조회해 선택 카테고리 **동등 평균**.
- **도보 기준**(마트·공원·생활체육·지하철): `(750m,1.0)—(1.5km,0.6)—(3km,0.2)—(6km,0)`.
- **거점형 차량 기준**(병원·도서관): `(5km,1.0)—(10km,0.6)—(15km,0.2)—(20km,0)`.
- `*_dist_m`은 EPSG:5186 투영과 1.291 보정이 끝난 설명용 거리이며 런타임에서 다시 계산하지 않는다.

## 9. Q4 돌봄·교육 — 가중치 **0.20** `[문서 원문]`
- 게이트: "필요 여부" → **아니요면 축 제외**.
- 예: 어린이집 / 유치원 / 초 / 중 / 고 복수 선택 → JSON 사전계산 점수 조회 → 동등 평균.
- **어린이집**: `(375m,1.0)—(750m,0.6)—(1.5km,0.2)—(3km,0)`(도보 5분).
- **유치원·초·중·고**: `(750m,1.0)—(1.5km,0.6)—(3km,0.2)—(6km,0)`(도보 10분).

## 10. Q5 취향 가게 — 가중치 **0.15** `[문서 원문]`
- 기본 칩 10종: 카페·편의점·헬스장·빨래방·동물병원·스터디카페·밥집·베이커리·미용실·약국. 최대 5개 선택하며 직접 입력은 제공하지 않는다.
- 처리: JSON의 반경 750m 점포 수와 건물 기준 사전계산 `*_score`를 조회해 선택 항목 백분위 **평균**.
- **모집단 = 후보군·호실이 아닌 부산 전 주택 건물 재고**(한 건물의 호실 수가 순위를 왜곡하지 않도록 함). 사전계산 테이블 조회.
- `vet_score`는 계산 불가이므로 0점 처리하지 않고 축에서 제외한다. `pharmacy_score`는 원자료 안내에 따라 변별력이 낮음을 고지한다.

## 11. Q6 동네 분위기 — 가중치 **0.10** `[문서 원문]`
- 입력: 0(조용)~1(번화) 연속 슬라이더 `t`, 또는 "상관없어요".
- 사전계산: `c`=반경 750m 전체 상가 수의 건물 백분위, `n`=소음업종 구성비의 건물 백분위.
- 런타임:
  `S = (1 - |c-t| / max(t, 1-t)) × (1 - 0.5 × n × (1-t))`.
- "상관없어요"면 축을 제외하고 남은 축 가중치를 재분배한다.

## 12. 최종 점수 & 가중치
| 축 | 가중치 |
|---|---|
| 자주 가는 장소 | 0.30 |
| 기반시설 | 0.25 |
| 돌봄·교육 | 0.20 |
| 취향 가게 | 0.15 |
| 동네 분위기 | 0.10 |
합 = 1.00.

- **축 제외 시 처리**: 남은 축의 원 가중치 비율을 유지하면서 합이 1이 되도록 재정규화한다.

## 13. 결과 설명 방식 (필수)
점수만 노출 금지. `RecommendationReason[]`로 정성 문구 + 원본값 동시 제공. 예:
- "보증금·월세가 예산 안에 있어요" (Q0)
- "자주 가는 곳까지 예상 보정거리 7.2km" (Q2 raw)
- "선택한 기반시설 중 5개가 가까워요" (Q3)
- "카페·생활편의 밀도가 부산 전체 주택 중 상위 20%" (Q5 백분위)
- "소득 기준은 실제 모집공고에서 다시 확인해야 해요" (자격 병렬 고지)

각 항목은 산정 근거·원본 값을 펼쳐볼 수 있게 한다.

## 14. 화면 상태 / 예외
- `STAGE2_IN_PROGRESS` · `FILTER_EMPTY`(완화 제안) · `ANALYZING` · `HAS_RESULTS` / `NO_RESULTS`.
- 지오코딩 실패/좌표 없음 → Q2 축 제외 + 안내.
- 주택별 특정 축이 전량 결측이면 0점이 아니라 해당 축을 제외한 뒤 남은 가중치를 재정규화한다.

## 15. 접근성 / 개인정보 / 백엔드 / 완료조건
- 접근성: 각 축 상단 "왜 묻는가" + 가중치 배지, 건너뛰기 버튼 포커스 가능.
- 개인정보: 주소는 좌표 변환 후 원문 저장 최소화, URL 쿼리 금지.
- 백엔드: `geo`·`facilities`·`percentile`·`recommendation` adapter가 교체 지점.
- 완료조건: mock 데이터로 §3 파이프라인이 정성 근거까지 산출, 가중치/계단/우회계수 전부 config, `[정책]` 항목 플래그화.
