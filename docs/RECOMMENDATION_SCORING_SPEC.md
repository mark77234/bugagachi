# RECOMMENDATION SCORING SPEC — 2단계 상권·취향 추천

> **Source of Truth:** 첨부 2단계 문항·로직. 가중치·계단 breakpoints·우회계수는 원문 그대로.
> 표기: `[문서 원문]` / `[정책 결정 필요]`.

## 1. 목적
1단계를 통과한 주택만을 대상으로, 예산·지역 하드필터를 적용하고 5개 취향 축을 0~1 점수로 산정해 가중합으로 순위화한다. **자격 값은 이 파이프라인에 입력하지 않는다**(혼합 금지).

## 2. 사용자 시나리오
- 자격 통과 12개 주택 → 예산 필터 8개 → 지역 필터 5개 → 취향 점수화 → 정성 근거와 함께 정렬 노출.
- 돌봄·교육 불필요 사용자 → 해당 축 제외 → 남은 축 재정규화 `[정책 결정 필요]`.

## 3. 파이프라인 (순수함수 체인, `services/recommendation`)
```
passedUnits (1단계 PASS 주택)
 → applyBudgetFilter(units, Q0)      // 하드필터, 점수화 X
 → applyRegionFilter(units, Q1)      // 하드필터, 점수화 X
 → (0개 → RelaxSuggestion 반환)
 → units.map(u => {
      axis = {
        frequent:     Q2 answered ? scoreFrequent(u, dests)      : null,   // 0.30
        infra:        Q3 answered ? scoreInfra(u, cats)          : null,   // 0.25
        education:    Q4.enabled  ? scoreEducation(u, cats)      : null,   // 0.20
        store:        Q5 answered ? scoreStore(u, sel, dist)     : null,   // 0.15
        neighborhood: Q6 answered ? scoreNeighborhood(u, mood)   : null,   // 0.10
      }
      weights = normalize(answeredAxes)     // [정책] 재정규화(권장) vs 0점
      final   = Σ(axis[k] * weights[k])     // ∈ [0,1]
      reasons = buildReasons(axis, rawValues)
   })
 → sort(final desc)
```

## 4. 공통 유틸: 계단형 점수 (선형보간)
```ts
// breakpoints: [{d: 거리, s: 점수}, ...] 오름차순. 구간 사이 선형보간, 밖은 clamp.
stepScore(distance, breakpoints) → number ∈ [0,1]
```

## 5. Q0 예산 (하드필터, 필수) `[문서 원문]`
- 입력: 보증금 최대(만원), 월 임대료 최대(만원).
- 처리: 초과 주택 **제거**(점수화 금지 — "예산 밖인데 상위 노출" 모순 방지).
- **순위 미상 시 2·3순위(더 높은) 임대조건 기준으로 보수적 필터링.** 주택의 `RentalCondition[]` 중 가장 비싼 조건으로 초과 판정. `[문서 원문]`
- 0개 → 예산 완화 제안 UI(현재 컷 대비 근접 주택 수 표시).

## 6. Q1 지역 (하드필터) `[문서 원문]`
- 입력: 부산 구·군 복수 선택 + "상관없어요".
- 처리: 선택 구·군 주택만 유지("상관없어요"=전체). 점수화 X. 0개 → 지역 완화 제안.

## 7. Q2 자주 가는 장소 — 가중치 **0.30** `[문서 원문]`
- 입력: 도로명주소 + 사용자 지정 라벨(복수).
- 처리: 지오코딩 → 좌표변환 → **보정거리 = 직선거리(Haversine) × 1.291**(부산 평균 우회계수) → `stepScore`.
- 계단: `(5km, 1.0) — (10km, 0.7) — (30km, 0)` 선형보간.
- **다목적지 결합: 평균** `[정책 결정 필요 P4]`(권장: 단순 평균).
- 프론트: 실제 주소 API 없이 **mock 자동완성 + 샘플 좌표**. adapter(`services/geo/geocoder`)로 추후 실 API 교체.

## 8. Q3 필수 기반시설 — 가중치 **0.25** `[문서 원문]`
- 입력(복수): 종합병원 / 대형마트 / 공원 / 도서관 / 생활체육시설 / 지하철역.
- 처리: 카테고리별 **최근접 시설 거리** → 점수 → 선택 카테고리 **동등 평균**.
- **도보 기준**(마트·공원·도서관·생활체육·지하철): `(750m,1.0)—(1.5km,0.6)—(3km,0.2)—(6km,0)`.
- **종합병원 차량 기준**: `(5km,1.0)—(10km,0.6)—(15km,0.2)—(20km,0)` — 병원급을 차량 시설로 분류(도보 기준이면 전 주택 거의 0).
- 데이터(현재 mock, 실제 미파싱): `부산 지하철 주소 위경도 매핑.csv`, `건강_병원_부산광역시.csv`, `부산광역시_15분 도시공원_20251119.csv`, `생활_대규모점포_부산광역시.csv`, `부산_체육시설_위치정보.csv`, `부산 유초중고 도서관.csv`.

## 9. Q4 돌봄·교육 — 가중치 **0.20** `[문서 원문]`
- 게이트: "필요 여부" → **아니요면 축 제외**.
- 예: 어린이집 / 유치원 / 초 / 중 / 고 복수 선택 → 카테고리별 최근접 → 동등 평균.
- **어린이집**: `(375m,1.0)—(750m,0.6)—(1.5km,0.2)—(3km,0)`(도보 5분).
- **유치원·초·중·고**: `(750m,1.0)—(1.5km,0.6)—(3km,0.2)—(6km,0)`(도보 10분).
- 데이터: `부산 유초중고 도서관.csv`, `부산 어린이집.xls`.

## 10. Q5 취향 가게 — 가중치 **0.15** `[문서 원문]`
- 기본 칩 10종: 카페·편의점·헬스장·빨래방·동물병원·스터디카페·밥집·베이커리·미용실·약국. + 직접 입력(상호/업종).
- 처리: 주택 **반경 750m 내 선택 업종 점포 개수** → **부산 전체 주택 재고 기준 백분위(0~1)** → 선택 항목 백분위 **평균**.
- **모집단 = 후보군 아닌 부산 전 재고**(소규모 후보군에서 1개 차이 증폭 방지). 사전계산 테이블 조회.
- 직접 입력: 입력 상호/업종의 반경 750m 내 개수로 동일 처리.
- 데이터: `buld_CMSC_M_NM_counts.csv`, `buld_CMSC_S_NM_counts.csv`. 백분위 분포는 `mocks`에 사전계산본 배치 `[정책 P6]`.

## 11. Q6 동네 분위기 — 가중치 **0.10** `[문서 원문]`
- 입력: 조용한 / 적당한 / 번화한.
- 처리: 부산 상가 밀집지(상권)까지 거리로 판단(가까울수록 번화, 멀수록 조용, 중간=적당).
- **정확한 상권 거리 경계 미확정 → `[정책 결정 필요 P2]`.** 프론트는 `scoring-config.ts`의 **임시 mock 경계** 사용, 화면 컴포넌트 비의존. 기준 변경 시 config만 수정.

## 13. 결과 설명 방식 (필수)
점수만 노출 금지. `RecommendationReason[]`로 정성 문구 + 원본값 동시 제공. 예:
- "보증금·월세가 예산 안에 있어요" (Q0)
- "자주 가는 곳까지 예상 보정거리 7.2km" (Q2 raw)
- "선택한 기반시설 중 5개가 가까워요" (Q3)
- "카페·생활편의 밀도가 부산 전체 주택 중 상위 20%" (Q5 백분위)
- "소득 기준은 실제 모집공고에서 다시 확인해야 해요" (자격 병렬 고지)

각 항목은 산정 근거·원본 값을 펼쳐볼 수 있게 한다.
